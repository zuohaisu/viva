# 0.3.8 封板：herdr 能力对照表（#156）

基线：`v0.3.7` = `252a543`。对照对象：herdr 0.9.3，`herdr --default-config` 的 `[keys]` 段。
证据存放在 `docs/validation/evidence/v0.3.8-seal/`：`screens/` 是真实 CLI 屏幕，
`walkthrough/` 是两个真实 workbench 的屏幕抓取。路径和主机名已经替换掉。

状态只有三种写法：**0.3.7 已有**、**0.3.8 新增**、**排除**。“已验证”只写有测试或真实走查的部分，
没有核对的规则写“未验证”。

## 旧 workbench 单键

0.3.7 的 `on_key` 直接绑定单键：在 spaces 列表上 `o` 开 shell、`p` 开 Pi、`d` 看 diff、`f` 浏览文件、`D` 清理 worktree、`h` 打开 handoff，`Enter` 开 shell；单独的 `q` 退出；`Ctrl+方向键` 移动 pane 焦点；`Ctrl+]` 离开 terminal 模式。0.3.8 删掉了这个处理函数。

| 键 | terminal 模式 | 其他模式 |
| --- | --- | --- |
| `Enter`、`o`、`p`、`d`、`f`、`D`、`h`、单独的 `q`、`Ctrl+方向键`、`Ctrl+]` | 全部原样送进 pane | `o`、`p`、`d`、`f`、`D`、`h`、`q`、`Ctrl+方向键`、`Ctrl+]` 都不触发界面动作。`Enter` 只在列表上做 herdr 的“选中”：进入选中的 terminal，或者切到选中的 worktree，不再开新 shell（`enter_on_worktree_selects_scene_without_opening_shell`）。 |

测试：`every_retired_workbench_key_is_forwarded_or_inert`（本 PR 新增，覆盖整张表）、`retired_keys_reach_the_pane_in_terminal_mode`。
本 PR 顺带修了一处：列表移动原来不看修饰键，`Ctrl+上/下` 还会移动选中行。现在列表移动只认不带 Ctrl / Alt 的键。

浮层里的单字母键属于浮层自己（比如右键菜单里 `q` 关闭菜单，goto 里 `d` 筛出已完成），不是旧 workbench 的动作。

## 键位差异

默认键位一致。下面这些是配置语法或者非默认项的差异，0.3.8 不处理：

- `keys.remote_image_paste`（只在 herdr `--remote` 下生效）：Viva 没有 `--remote`，读到会提示 unknown 并忽略。
- `[keys.indexed]`（herdr 留着兼容旧配置）：不解析。
- `zoom` 的旧别名 `fullscreen`、`extra_prefixes`：不支持。Viva 的 `prefix` 可以写成列表。
- 按键语法：不接受 `cmd` / `super`；命名标点只认 `minus`、`question`、`bracketleft`。
- `[[keys.command]]`：`command` 是 Viva 的命令 id（比如 `viva.diff`），没有 herdr 的 `type` / `width` / `height`。
- `last_pane`：两边默认都不绑定。Viva 绑定后是循环到下一个 pane，herdr 是在两个 pane 之间来回切换。
- `copy_mode = "prefix+["` 和 `swap_pane_* = "prefix+shift+h/j/k/l"` 不在 herdr 打印的默认配置里，但 herdr 二进制认这两个键名，并且内置了同样的默认值。

## 两个真实 workbench 走查

环境：Linux，0.3.8 debug 构建，同一个 `VIVA_HOME`，两个 tmux 会话（A、B）里各开一个 `viva`。

| 核验项 | 结果 | 证据 |
| --- | --- | --- |
| 一端分屏或改名，另一端看到同一棵 scene / tab / pane 树 | 通过。A 分屏并把 tab 改名为 `build`，B attach 后看到同样三个 pane 和新名字 | `walkthrough/03-B-attach.txt`、`04-B-after-rename.txt` |
| 两个客户端看同一个 tab，后一次尺寸改动决定 pane 尺寸 | 通过。B 把内层分隔调到 40，A 跟着变；A 再调到 55，B 跟着变；server 树里也是 55 | 分隔线列位置和 `viva scene list` |
| 两个客户端看不同 tab 时互不影响 | 通过。A 在 `build` 上调尺寸，B 在另一个 tab 上调尺寸，各自只改自己的 tab | `viva scene list` |
| 刷新后本客户端停在自己的 tab，侧边栏宽度不被另一端改掉 | 通过。B 拖宽侧边栏到 31，A 仍是 25；A detach 再 attach 后还在 `build`，B 仍是 31，也还停在自己的 tab。注意：重新启动的客户端没有之前的身份，它拿到的是最后一次保存的视图 | `walkthrough/05-B-reattach.txt`、`06-A-reattach.txt` |
| 关闭 pane 后，pane 里的进程仍在跑 | 通过。在 pane 里跑每秒写一次文件的循环，`prefix+x` 关掉 pane 后文件继续更新；B 也看到 pane 消失 | `walkthrough/07-A-closed.txt` |

走查中发现并在本 PR 修掉的问题：

1. 新 tab 的第一次分屏比 tab 本身先到 server，界面显示 `tree update failed: not found: scene/tab`，之后靠布局同步才对上。现在先保存新 tab，再发分屏（`a_new_tab_reaches_the_server_before_its_first_split`）。`walkthrough/02-A-split.txt` 是修之前的屏幕。
2. tab / pane 改名框把 `Ctrl+U` 当成字母 `u` 输入。现在 `Ctrl+U` 清空，其他 Ctrl 组合不输入字符（`rename_prompts_clear_on_ctrl_u_and_never_type_control_letters`）。
3. server 被杀后 `viva` 无法启动，见上面的“server 重启恢复”。
4. resize 模式在默认配置下没有任何键能用，见上面的“键鼠与三种模式”。

## 排除项

- 插件市场和 herdr.dev：不做。插件只从本地目录安装，URL 被拒绝。
- 远端 manifest 热更新：不做。屏幕规则编译在二进制里。
- Linux logind：不做。
- Windows：不做。发布产物只有 macOS（arm64 / x64）。
- 复制 herdr 源码：不做。只对照行为和公开的默认配置。
- 用屏幕状态关闭任务：不做。屏幕读数不会写任务结果或记忆。
- 第二套命名 session：不做。`VIVA_HOME` 就是 session。
