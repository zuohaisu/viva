# Viva v0.3.0

The V15 workbench-deepening series, grown from a day of real herdr use
([implementation notes](../implementation/v15-workbench-deepening.md)), plus
the QA-hardening fixes it went through.

## Added

- **File browser (V15-1)**: `f` in the workbench opens a worktree's file
  inventory (porcelain statuses, changed files first). `Enter` views a
  modified file as a diff against the worktree's recorded base SHA, or
  bounded content for clean/untracked files; the binary verdict is honest;
  paths are validated (relative, no `..`); `e` opens the file with the
  system opener.
- **PR cleanup (V15-2)**: worktree rows show PR state via `gh` (60s cache;
  unknown stays unknown). `D` twice — naming the exact path — releases and
  removes a worktree whose PR is MERGED, re-checked live and audited;
  closed/unknown states refuse.
- **Agent handoff (V15-3)**: `h` hands a worktree to another agent. The
  brief carries the task goal, the branch and the departing agent's last
  controlled summary, delivered into the new terminal; the departing
  terminal keeps running; the handoff lands in task history and the audit
  log.
- **Auto-sync (V15-4)**: `viva sync auto-pull on|off` (default OFF,
  persists) and `viva sync status`. When on, active projects' MAIN
  checkouts fast-forward (`--ff-only`, clean tree only, 5-minute TTL,
  off-thread, pause-gated, audited); task worktrees are fetched, never
  merged; rows show ahead/behind vs origin; failures degrade to a status
  note.
- **Rate-limit recovery (V15-5)**: agents report `rate_limited` with a
  required RFC3339 `reset_at`; the resident server sweeps due plans once a
  second and prompts the terminal to continue. Plans persist across
  restarts; overdue ones expire with a record instead of executing blindly.
  `viva recovery list | schedule --terminal <id> --at <rfc3339> [--task
  <id>] | cancel --id <n>`.

## Hardening

The series went through six QA rounds; notable fixes: char-boundary-safe
diffs, single-flight sync and fetch-gate splitting, owner-only toggles,
cleanup lock split, protocol timeouts carried through, and a terminal
reader that survives `EINTR`/`EAGAIN` (the CI high-volume flake root
cause).

## Safety and limitations

- All socket-mutating V15 requests sit behind the existing grant gate
  (ADR 0007); every outcome lands in the office event log.
- Auto-sync never merges task worktrees and never runs on dirty trees;
  member-initiated dispatch and stopping still require a live grant.
- `gh`-derived PR state is cached for 60s and unknown when `gh` is absent;
  cleanup refuses on unknown state.
- No schema migration: existing VIVA_HOME state opens as-is.
